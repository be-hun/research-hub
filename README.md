# Research Hub

Temple ResearchConnect: a research discovery site that shows the research happening across Temple University colleges, built from public records of grants (NIH, NSF, other federal agencies), clinical trials and funded publications. Built for the Temple AI Build Challenge (<https://ibit.temple.edu/aibuild/>; confirm current deadlines and requirements in the official guidelines).

## Status

| Area | State |
| --- | --- |
| Frontend (`frontend/`) | v4 redesign: Home, Explore, Search, Topics, Award, People, Colleges, Profile demo, Ask, About. All real data. |
| Backend (`backend/`) | Five sources (NIH, NSF, USAspending, ClinicalTrials.gov, OpenAlex), overview, topics, search with facets, grounded assistant (Anthropic `claude-sonnet-5-5` by default; Gemini optional). |
| API contract | `backend/app/models.py` is the source; `frontend/src/lib/types.ts` and the endpoint table in [docs/api.md](docs/api.md) are generated by `uv run python -m app.contract`. |

## Run the frontend

Start the backend first (below), then:

```bash
cd frontend
npm install
npm run dev   # http://localhost:3000, forwards /api/* to http://localhost:8000 (override with API_URL)
```

## Run the backend

The backend stores everything in Postgres: Supabase in production, a local Postgres for development and tests.

```bash
brew install postgresql@17 && brew services start postgresql@17   # once
createdb research_hub && createdb research_hub_test                # once
cd backend
cp .env.example .env                   # DATABASE_URL defaults to the local research_hub database
uv sync
uv run python -m ingest.run            # fetch every source into the database (about 2 minutes)
uv run python -m ingest.run --offline  # reload from the cached raw JSON, no API calls
uv run python -m app.backup             # pg_dump the app's tables to data/backups/
uv run uvicorn app.main:app --reload            # http://localhost:8000/api/health
uv run pytest                          # each test gets its own schema in research_hub_test (TEST_DATABASE_URL)
```

To use Supabase, set `DATABASE_URL` in `backend/.env` to the project's **Session pooler** URI (Project > Connect),
ending in `?sslmode=require`, and run `uv run python -m ingest.run --offline` once to fill it. Only the backend holds
this connection string; the browser still calls `/api/...`, and every table has row level security with no policies,
so Supabase's public Data API can't read them.

| Source | What | Notes |
| --- | --- | --- |
| NIH RePORTER | Grants, FY2022 onward | Department gives the college |
| NSF Award Search | Grants active since 2022 | College inferred from the directorate |
| USAspending.gov | Other federal agencies' grants (DOD, DOE, ED, NASA, ...) | Research programs only; NIH/NSF skipped as duplicates |
| ClinicalTrials.gov | Trials sponsored by Temple or run at a Temple site | Status ("Recruiting") from the registry |
| OpenAlex | Articles since 2024 with a Temple author and a reported funder | Affiliation gives the college; optional `OPENALEX_API_KEY` in `.env` |

Mapping rules live in `backend/app/colleges.py` (colleges), `backend/ingest/funders.py` (funding types, inferred from names) and `backend/app/topics.py` (topics: funder institute for grants, title keywords otherwise). People are matched across sources by first and last name.

## Current architecture and next launch work

The current prototype uses FastAPI and Postgres (Supabase) with full-text search, a Next.js 14 App Router frontend, five public
data sources, and one backend AI wrapper. Search, filters, counts, and charts are ordinary database queries.
The assistant retrieves records first and only returns database-backed cards and citations.

The next launch increments are:

1. Add researcher profiles and confidence-aware identity matching.
2. Add college dashboards, comparisons, and collaborator discovery with database-computed scores.
3. Add scheduled ingestion, external backups, freshness alerts, and a review path for mapping corrections.
4. Add authentication only for saved searches and faculty-submitted corrections; public records remain read-only.
5. Add shared rate limiting, model budget accounting, error tracking, structured logs, and deployment rollback.
6. Upgrade Next.js on a planned dependency cycle rather than during Demo Day hardening.

### Data and AI rules (from the project plan)

- Every record carries its source, verification status and last-updated date. The two verification values are `faculty-confirmed` and `public-award-record`.
- An award record is funding history, not proof that a study is active or recruiting.
- AI must not invent projects, investigators or citations. Use ordinary SQL for filters, sorting and exact matching, and AI for natural-language search and comparing research interests.
- Keep the AI behind an internal wrapper, never called from the frontend.
- Use public data and synthetic profiles for the demo unless a faculty member has explicitly approved using theirs. Keep API keys and private data out of GitHub.
- Include Lewis Katz School of Medicine research when it has a documented connection to another Temple unit.

## Known gaps

- Search is keyword-based; AI interpretation of natural-language questions is not built yet.
- The assistant needs the selected provider key in an untracked `backend/.env` (copy `backend/.env.example`). Anthropic is the default; Gemini is opt-in.
- About 30 awards have no college (mostly NSF social-science awards whose PIs have no other awards).
- The "Cancer" and several smaller topics have no photo and use a plain tile.

## Production and Demo Day checklist

- Never commit `backend/.env`; copy `.env.example` and set credentials in the process environment or a root-owned secret file.
- Rotate any credential that has ever appeared in Git history. Removing the file does not revoke the credential.
- Put the site behind HTTPS and expose `/api/health` through the reverse proxy.
- The assistant has no per-client rate limit and accepts up to eight conversation messages per request; add shared rate limiting before a public launch. Set `AI_TIMEOUT_SECONDS` for the provider timeout.
- `ingest.run` dumps the current data to `backend/data/backups/` (`pg_dump`) before every import, and loads the new data in one transaction so the site never shows a half-finished import. Keep backups outside the deploy volume in production and retain the prior database until the new run is verified. Use `--no-backup` only for a deliberate local operation.
- Run `uv run pytest` and `npm run build` before deployment. CI runs both on pushes and pull requests.
- Deploy only a commit on `main`, following [docs/deploy.md](docs/deploy.md).

The production plan in this README is intentionally a runbook, not a proposal for a different stack. Supabase Postgres is the database; a real launch additionally needs Supabase's managed backups turned on, scheduled refreshes, non-root services, HTTPS, monitoring, and an identity-review workflow.
